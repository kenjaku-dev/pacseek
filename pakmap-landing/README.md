# pakmap-landing

Landing site for [pakmap](https://github.com/kenjaku-dev/pakmap) — a Next.js 16
(App Router, Turbopack) single page, Tailwind CSS v4, framer-motion, exported
statically for GitHub Pages.

## Prerequisites

pnpm is pinned via `package.json#packageManager` (`pnpm@12.5.1`):

```bash
npm i -g pnpm@12.5.1
pnpm install --frozen-lockfile
```

## Develop

```bash
pnpm dev             # http://localhost:3000
pnpm lint            # eslint
pnpm typecheck       # next typegen + tsc --noEmit
pnpm build           # static export → out/
```

CI (`.github/workflows/pages.yml`) runs lint → typecheck → build on every push
that touches `pakmap-landing/`.

## Conventions

- **Single page** — `src/app/page.tsx` composes sections from
  `src/components/` (`ui/` = primitives, `chrome/` = header/nav/footer parts).
- **Design tokens** — `src/app/globals.css` (CSS custom properties mapped into
  Tailwind via `@theme inline`). Master reference:
  `design-system/pakmap/MASTER.md`; the palette table there mirrors `globals.css`.
- **Module alias** — `@/*` → `src/*` (`tsconfig.json`).
- **Version** — read from the generated `src/lib/version.ts`
  (`pnpm sync-version` regenerates it from the repo root `Cargo.toml`;
  `predev`/`prebuild` run it automatically). Commit the regenerated file in the
  same PR as a crate version bump — never hardcode a version elsewhere.
- **Content accuracy** — keybindings and feature claims must match the Rust
  TUI (`src/tui/app.rs`, root `README.md`). When the binary changes behavior,
  update the landing copy in the same PR.

## Deploy (GitHub Pages)

`pages.yml` builds the static export with the project base path:

```bash
NEXT_PUBLIC_BASE_PATH=/pakmap pnpm build   # project Pages: /<repo-name>/
```

- Site URL: `https://kenjaku-dev.github.io/pakmap/` (project site → base path
  is `/pakmap`; that's what pages.yml sets via `NEXT_PUBLIC_BASE_PATH`).
- `next.config.ts` maps `NEXT_PUBLIC_BASE_PATH` to `basePath`/`assetPrefix`.
- In-page navigation is hash-anchor only, so links survive under the base path.
- `robots.txt` and `sitemap.xml` are generated by `src/app/robots.ts` and
  `src/app/sitemap.ts` (absolute URLs, already include the base path).
- `metadataBase` in `src/app/layout.tsx` matches the Pages URL.
